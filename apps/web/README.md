# TrustLayer web

Phase 3A interface foundation, Phase 3B injected wallet/deployment verification and Phase 3C client/freelancer escrow workflows. Verified connected wallets see actual projects, allocations and bounded event history, and can create, approve tokens, fund, accept, submit a hash, approve payment or release after review timeout. Preview data stays explicitly labeled. Dispute/juror actions, backend and private evidence storage remain deferred.

From the repository root, install with `npm.cmd --prefix apps/web ci`, then run `npm.cmd run web:dev`. Open http://127.0.0.1:3000. Refreshing resets draft forms, sample/empty mode and preferences; wallet connection is explicit after reload. Sample views work without a node. Live reads require a persistent Phase2D deployment on port 8545 and a fresh non-ephemeral export. Dev/build syncs public deployment metadata automatically.

See [Phase 3C](../../docs/PHASE3C.md) for exact local setup, controlled token provisioning, contract mappings, tests, manual walkthrough and limitations, [Phase 3A](../../docs/PHASE3A.md) for design/routes and [Phase 3B](../../docs/PHASE3B.md) for the wallet foundation. Project descriptions and client transaction records are session-only; confirmed chain events can be reloaded separately. Do not copy contract ABIs or treat the checked-in ephemeral manifest as a live deployment. Compile from the root first to generate artifact type declarations. Unit tests use `npm.cmd --prefix apps/web run test:unit`; browser tests use `npm.cmd run web:test` after building. `npx.cmd hardhat run apps/web/scripts/verify-escrow-workflow.ts` runs the actual-contract integration on its own in-process EVM. Stop after Phase 3C for review.
