# TrustLayer web

Phase 3A interface foundation, Phase 3B wallet/deployment verification, Phase 3C escrow workflows, Phase 3D dispute/juror integration and Phase 4A backend authentication. Verified connected wallets can open/respond/vote/finalize disputes, register/stake/withdraw as jurors and claim assigned rewards through the actual contracts. Phase 4A adds separate SIWE sign-in, PostgreSQL profiles and authorized project metadata APIs. Preview data stays explicitly labeled. Private evidence storage, refunds and treasury administration UI remain deferred.

From the repository root, install with `npm.cmd --prefix apps/web ci`, then run `npm.cmd run web:dev`. Open http://127.0.0.1:3000. Refreshing resets draft forms, sample/empty mode and preferences; wallet connection is explicit after reload. Sample views work without a node. Live reads require a persistent Phase2D deployment on port 8545 and a fresh non-ephemeral export. Dev/build syncs public deployment metadata automatically.

See [Phase 3D](../../docs/PHASE3D.md) for contract mappings, tests, MetaMask walkthrough and limitations, [Phase 3C](../../docs/PHASE3C.md) for setup/controlled provisioning and [Phase 3B](../../docs/PHASE3B.md) for wallet validation. Project creation descriptions, non-sensitive form inputs and client records remain memory-only; confirmed events reload separately. Do not copy ABIs or treat ephemeral exports as live deployments. Compile first to generate artifact types. Unit tests use `npm.cmd --prefix apps/web run test:unit`; browser tests use `npm.cmd run web:test` after building (PLAYWRIGHT_PORT=3001 preserves an app on port 3000). Existing `verify-escrow-workflow.ts` and `verify-arbitration-workflow.ts` run with `npx.cmd hardhat run apps/web/scripts/<filename>` on isolated EVMs. The new `verify-backend-workflow.ts` also uses an isolated PostgreSQL engine. See [Phase 4A](../../docs/PHASE4A.md) for server-only environment configuration, migration/role setup, SIWE/API details and test results. Run `npm.cmd --prefix apps/web run db:migrate` after configuring a database owner connection; use a separate restricted runtime login. No hosted connectivity is claimed by embedded tests. Stop after Phase 4A for review; uploads and Phase 4B require approval.
